# 0003 — v0.1 interaction loop

Status: accepted (2026-09-08)

## Decision

Ship v0.1 as a single static Go binary on one Ubuntu VPS:

- Telegram long polling (not webhooks): $0 delivery, no domain/cert/port.
- Single OpenAI-compatible inference call per turn via Chat Completions,
  configured by `LLM_BASE_URL` / `LLM_API_KEY` / `LLM_MODEL` so Sumopod and
  OpenRouter are env-swaps, not code paths.
- SQLite via `modernc.org/sqlite` (pure Go, `CGO_ENABLED=0`), WAL +
  `busy_timeout(5000)` in DSN, `MaxOpenConns(1)`, local disk only.
- Locked personal bot: numeric-ID allowlist, silent drop for strangers.
- No tool execution in v0.1: model output becomes reply text only.
- Idempotency via `telegram_updates(update_id)` claim-before-effect.
- systemd supervision with sandboxing; no container (saves ~100MB+ RAM,
  Docker default root daemon is not a security win here).

## Rationale

Long polling removes webhook ops (TLS, public URL, secret-token header)
while traffic is personal-scale. Chat Completions is the portable wire
format across Sumopod/OpenRouter/Ollama/vLLM; Responses API is OpenAI-only.
Single-writer SQLite matches the single-poller constraint (one process per
token anyway due to 409 Conflict).

## Exit path

- Webhooks when holding a poll connection becomes a measurable cost or a
  public HTTPS service already exists.
- Container (rootless, read-only FS) when tool/shell execution arrives.
- Postgres when multi-replica or write throughput outgrows SQLite.
